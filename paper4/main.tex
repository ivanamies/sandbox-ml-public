\begin{abstract}
% Simplified Technical English style: short active sentences, one idea per sentence.
We attach a small head to a frozen language model and train only the head.
The head predicts a random keyed hash of the token prefix from one activation vector.
The number of wrong bits is a syndrome.
A tampered activation gives a high syndrome.
On frozen GPT-2 the head detects a swapped residual vector with AUROC 0.964 to 0.978 at every layer tried.
Its false-positive rate at 95\% recall is 0.09 to 0.14 per token.
The head has 213 thousand parameters.
It costs 1.0\% of the forward pass at 124M parameters and 0.14\% at 6.9B on a GPU.
The clean floor is 15 to 17 wrong bits of 64.
The floor does not move from GPT-2 to Pythia 6.9B at matched depth.
Swap detection stays at AUROC 0.96 to 0.97 across that ladder.
The floor of a model trained with the head from scratch is 15 bits.
Cooperation buys nothing for detection.
The head finds the layer and the token of the intervention exactly.
The same head detects transplanted, replayed, and moved KV-cache entries with AUROC 0.95 to 0.97.
Averaged over 8 tokens the head gives zero false alarms at 95\% recall on swaps, transplants and replays.
Mahalanobis distance finds noise and steering that the head does not; the head finds swaps that Mahalanobis does not.
Fusing the two into one score is worse than keeping two instruments.
A two-sided statistic catches an attacker who drives the syndrome below the floor.
Thresholds set on prompt tokens do not transfer to generated tokens; a calibration set of a few hundred generations fixes it.
The seal does not detect prompt injection, small adversarial nudges, or an adversary who holds the key.
It is a seal on the channel between the model's own computations, not a judgment about what the model computed.
\end{abstract}

\section{Introduction}
Interpretability-by-design borrows the \emph{source coding} half of information
theory: make representations legible by making them sparse or discrete. This paper
uses the \emph{channel coding} half for a narrower and more operational purpose ---
integrity. A message authentication code (MAC) binds a piece of data to a key so
that any change is detectable; we show that a two-layer head, trained after the fact
on a frozen model, turns activation and KV-cache integrity into a cheap, calibrated
runtime check. The head predicts a keyed hash of the token prefix from a tapped
vector; the number of wrong bits is the syndrome; a swapped, replayed, transplanted
or transported-in-error vector fails the check. Everything is 3 seeds with error bars,
AUROC and FPR@95\%TPR, a Mahalanobis baseline on the same activations and an
untrained-head control in every table.

Section~\ref{sec:lessons} compresses the design lessons that led here (a designed
code on an MNIST encoder: what a syndrome can and cannot see); Section~\ref{sec:mac}
gives the MAC construction and its three threat models; Sections~\ref{sec:armf}--\ref{sec:armg}
are the headline: the retrofit on frozen GPT-2, what training-time cooperation
would add (nothing), and the KV cache; Sections~\ref{sec:armj}--\ref{sec:armh} stress the
instrument (fusion, the two-sided statistic, adaptive attackers, generation-time
calibration, a scale ladder to 6.9B); Section~\ref{sec:deploy} is the deployment
recipe. The codes-and-optimisation questions --- where SGD spends Hamming distance,
when a decoder matters, and whether a model trained against its own alarm can
smuggle bits through the checked code --- are the subject of a companion paper in this program that publishes after this one, and are not relied on here.

\section{Design lessons from a designed code}\label{sec:lessons}
\paragraph{Conventions (used throughout).} A representation $z\in\mathbb{R}^{128}$
is binarised as $s=\mathrm{sign}(z)$ through a straight-through estimator; bits are
$b=(1-s)/2$, so $s{=}+1\mapsto0$ and even parity over a check $\Leftrightarrow$ the
product of its signs is $+1$. The code is a rate-1/2 LDPC code with $n{=}128$,
$m{=}64$ checks, regular column weight 3 / row weight 6, built by a
progressive-edge-growth-style greedy construction with girth $\ge6$, seed 0, saved as
$H$. The hard syndrome of a vector is $H\,\mathrm{bits}(\mathrm{sign}\,z)$ over GF(2)
and its weight $w=\|H\,\mathrm{bits}\|_0$ counts violated checks. A \emph{systematic}
encoder emits 64 information logits and sets the 64 parity signs to the XOR (product
of STE signs) over the information set of the same $H$, obtained by GF(2) row
reduction; codewords are then valid by construction. Unit tests cover the sign/bit
map, a hand-computed check, agreement of hard syndrome and soft parity on random
codewords, and the min-sum decoder.

\paragraph{What the MNIST rungs taught.} We first tried to make a two-conv MNIST
encoder's binarised code lie on $H$ by a soft-parity loss (Nachmani-style products
$\prod\tanh(z_i/2)$ over each check, log-barrier form, annealed weight
$\lambda\in[0.3,30]$, two-sided margin with a box on $|z|$). Accuracy is never the
problem; parity is: every $\lambda$ plateaus at 92--95\% of checks satisfied. The
plateau is structural. On the trained models 90\% of test points sit at hard
syndrome weight 2--4, and hard-decision min-sum converges on only 10\% of them; with
girth $\ge6$ a weight-2 syndrome is at Hamming distance $\ge4$ from every codeword, so
these are trapping-set-like local minima of the syndrome-weight landscape. Minimising
syndrome weight is not minimising distance to the code, and gradient descent on the
product loss is a local search in that landscape (the lattice test of this
hypothesis is taken up by the later companion paper). The systematic encoder is on the code at 100\% of
checks with baseline accuracy (99.02\% vs 98.94\%; the sweep is in the repository).

The syndrome as a detector (Table~\ref{tab:r3}) then behaves as its construction
dictates. (i) For corruption of the \emph{representation channel} --- Gaussian noise
on $z$, a 50/50 coordinate splice --- the hard syndrome is a near-perfect detector
(0.95--1.00), competitive with Mahalanobis and better than max-softmax/energy, for the
price of 64 XORs and with designed semantics. (ii) For \emph{input-space} corruption
(FGSM/PGD, out-of-distribution digits) the systematic model's syndrome is exactly
0.5: every input maps to a valid codeword by construction. (iii) Whole-vector
patching --- replacing $z$ by another input's clean $z$ --- is 0.5 for \emph{every}
detector including the baselines: the swapped-in vector is a clean valid state. That
blind spot, shared by all three of the input-space failures, is what the MAC fixes:
the code certified $z$'s internal consistency, not that $z$ belongs to \emph{this}
input.

\section{The MAC: input-bound parity}\label{sec:mac}
We keep the systematic encoder and make the parity half key-dependent. A frozen,
randomly initialised 2-conv net (seed-fixed, weights never trained) yields 64
features, binarised at per-feature medians over the training set so key bits are
balanced: $k(x)\in\{0,1\}^{64}$; $f$ is a fixed permutation plus mask. A parity head
$p(z_{\rm info})$ (2-layer MLP, 256 hidden, trained with BCE against $f(k(x))$, weight
$\beta{=}3$; gradient reaches the encoder) sets the emitted parity to
$A\,u\oplus\mathrm{sign}(p)$. The check is
\[
\mathrm{syndrome}_{\rm MAC}(z,x)=H\,\mathrm{bits}(\mathrm{sign}\,z)\;\oplus\;H_{\rm par}\,f(k(x)),
\]
i.e.\ $z$ must lie in the coset $\mathcal{C}+[0\,|\,f(k(x))]$; it equals $H_{\rm par}$
applied to the head's key-prediction error and is zero iff that prediction is exact
(unit-tested by hand). Accuracy $98.96\pm0.05$\% ($-0.13$\%), 3 seeds.

Table~\ref{tab:mac} and Fig.~\ref{fig:mac}. Whole-vector patch swap --- invisible to
every detector in Table~\ref{tab:r3} including the baselines --- is detected at
$0.942\pm0.003$ (kill criterion was $\le0.7$). Non-adaptive input attacks and OOD,
structurally $0.500$ before, are now $0.70$--$0.88$ and $0.73$--$0.75$. The three
threat models, which we report for every instrument below: an attacker that ignores
the MAC still succeeds 97\% of the time but is flagged (AUROC $0.927$); a fully
adaptive \emph{key-public} attacker that adds the MAC hinge to its loss cuts detection
to $0.593$ (its own targeted success drops to 79\% because $f(k(x))$ is a moving target
under PGD); with the \emph{key secret} --- attacker optimising against its own random
key net --- detection is $0.970$. Limitation: the clean syndrome floor is
$15.3\pm0.2$ of 64 (head capacity and epochs do not move it; $\sim$5 key bits sit at
their thresholds and are unpredictable), so this is a statistical, not exact,
certificate.

\paragraph{Sidebar: an imperfect code that shifts is the better detector.} Replacing
the binary code by an E8 lattice (16 blocks of 8, exact nearest-point projection,
loss $\|z/s-Q(z/s)\|^2$; full treatment in the later companion paper) gives a code the network
sits \emph{near} but not on, and distance-to-lattice is the best all-round detector
in either setting: $0.98$--$0.99$ on FGSM/PGD, FashionMNIST and KMNIST (Mahalanobis
$0.51$--$0.95$, MSP $0.44$--$0.92$), $0.94$--$0.99$ on Gaussian $z$-noise, $0.925$ on
patch mix, and $0.500$ on patch swap. The fraction of examples within the decoding
radius grows monotonically with the loss weight (all blocks $<0.5\rho$: $0.126\to0.890$;
$<\rho$: $0.489\to0.977$ from $\lambda{=}0.1$ to $100$), with no plateau. ``Near the
code'' is what a good detector wants; ``on the code'' is what a MAC needs, and the
systematic construction gives it for free.

\section{Setup for frozen transformers}\label{sec:setup}
Part of the design was fixed by the MNIST results: statistical certificates are the
product (the cooperative MAC floor was 15.3/64 and never lower), learned binding is
the mechanism, three threat models are standard reporting. The rest of the paper asks
the only version of the idea the real world can buy: attach a head to a \emph{frozen}
pretrained LM, train only the head, and detect interventions on the residual stream
(Section~\ref{sec:armf}); measure what training-time cooperation would add with a
from-scratch control (Section~\ref{sec:arme}); and check the one place in a
transformer where memory corruption is literal, the KV cache (Section~\ref{sec:armg}).
All numbers are mean $\pm$ std over 3 seeds (seed = head initialisation + key net; the
LM is fixed), reported as AUROC and FPR@95\%TPR, with a Mahalanobis baseline on the
same activations and an untrained-head control in every table.

\paragraph{Shared machinery.} The key is a frozen random causal encoder: a random
token embedding into a frozen random GRU, per-feature median-binarised on the
head-training corpus (balanced bits), followed by a fixed permutation and mask; $k_t$
depends only on tokens $\le t$ (unit-tested, incremental $=$ offline), so it is
computable during generation. The head is a 2-layer MLP (256 hidden) reading the
tapped vector at one layer, trained with BCE to predict $f(k(x_{\le t}))$; the per-token
syndrome is the number of wrong bits. There is no code to decode to on a frozen model:
this is detection only, and the ``syndrome'' is exactly the key-prediction error.
Model: GPT-2 small (124M) frozen; head-training corpus 2M TinyStories tokens in
128-token windows, evaluation 200k disjoint tokens, OOD $=$ Python source. Corruptions
are injected by forward hooks at layer $m$ on positions $t\ge32$; clean and corrupted
tokens at those positions are the two classes. Sections~\ref{sec:armf}--\ref{sec:deploy}
were run on Apple MPS in fp32; Sections~\ref{sec:armj}--\ref{sec:armh} on one RTX~3090\,Ti,
where the Section~\ref{sec:armf} table reproduces to within 0.005 AUROC and 0.1 bit
of floor.

\section{A post-trained MAC head on frozen GPT-2}\label{sec:armf}
\emph{Census-side, in the sense that matters commercially: \textbf{we did not touch the
model.} This is a small head trained on activations read out of a frozen language model
--- not a LoRA, not a fine-tune, not an adapter inside the forward pass. No LM gradients
are taken at any point, the weights are byte-identical before and after, and the head can
be attached to and detached from a deployed model without changing a single thing it
computes. That is the whole story of this section, and every number below should be read
against it.}

Table~\ref{tab:armf}, Fig.~\ref{fig:armf}. \textbf{The retrofit works.} A 213k-parameter
head, four epochs on 2M tokens, no LM gradients, detects a swapped residual --- the
activation-patching operation --- at AUROC $0.964$--$0.978$ with FPR@95\%TPR
$0.09$--$0.14$, at every layer tried; the kill criterion was $0.7$. Overhead is 7--11\%
of the LM forward on MPS (1\% and falling on a GPU, Section~\ref{sec:armh}). The
untrained head is $0.50$ everywhere.

\textbf{The frozen floor equals the cooperative floor.} $15.2$--$16.6$ bits vs.\ the
$15.3$ of a model trained with the head from scratch (Section~\ref{sec:mac}). GPT-2's
residual stream already carries $\sim$80\% of a random causal hash of the prefix per
bit; per-bit error is uniform ($0.16$--$0.24$ at hidden 1024, no unlearnable bits).
Capacity lowers the floor ($18.2\to12.5$ from hidden 64 to 4096); corpus size barely
does ($17.6\to15.6$ from 50k to 2M tokens). This was the number the design called
central, and it is essentially free.

\textbf{Localization is exact.} Layer bracketing gives a clean step matrix: heads at
$\ell\in\{3,6,9\}$ against swaps at $m\in\{3,6,9\}$ read $[.98,.50,.50;\,.97,.97,.50;\,
.96,.96,.96]$ --- a head fires iff the intervention is at or below its layer. Temporally,
a single swapped token raises the syndrome by $16.1$ at $t^*$ and by $0.0$ afterwards
(single-token AUROC $0.974\pm0.001$; argmax hits $t^*$ 40\% of the time, the miss being
clean-floor variance across 127 other positions).

\textbf{Complementary, not dominant.} Mahalanobis on the same residuals is $0.500$ on
swap (a swapped activation is a perfectly typical activation) and $0.99$--$1.00$ on
Gaussian noise, steering and OOD, where the MAC is $0.55$--$0.97$. Ablating one attention
head is invisible to both. \textbf{Generation-time} the floor is stable
($15.4$--$16.0$ on prompt tokens, $16.7$--$17.2$ on greedy-generated ones).

\section{The cooperative control}\label{sec:arme}
Would a model trained \emph{with} the head from the start detect more? A 4-block
decoder-only transformer ($d{=}256$) on a 256-state DFA-tracking task, with the
systematic$+$MAC bottleneck after block 3 and block 4 reading only the codes (the
task, the recurrent-code recipe and the correction-side results belong to the later companion paper).
Table~\ref{tab:ef}: \textbf{the E$-$F delta is $\approx0$ where it matters.} Swap
$0.944$ vs.\ $0.973$; the cooperative model's advantage on Gaussian noise
($+0.13$--$+0.28$) is because the bottleneck signs \emph{are} the noised object.
Cooperation buys nothing for detection that the frozen residual does not already
give.

\section{KV-cache integrity}\label{sec:armg}
Same frozen GPT-2; heads on the flattened K, V, or [K$|$V] of one layer, with fixed
sinusoidal \emph{slot} features appended and inputs standardised, target
$f(k(x_{\le t}))$. Two designs that XOR a random per-slot mask into the target (with or
without slot features) are unlearnable for a shallow head --- floor $=$ chance, both
nulls kept --- and unnecessary: prefix binding alone makes any moved entry fail at its
new slot. Corruptions act on the cache tensors, positions $\ge32$.

\paragraph{Is the floor a property of the stream or of our reader?} It is a fair
objection to the flat-floor claim, and it is stated here rather than in a trailing
limitation because the answer changes what the row means. Head capacity moves the floor
substantially while corpus size barely does, and per-bit error is uniform --- the
signature of a global capacity constraint rather than of intrinsically hard bits. If
the head were the binding constraint, ``flat from 124M to 6.9B'' would be a fact about
our 213k-parameter reader, not about the models. The discriminating test is to compare
\emph{asymptotes} in reader capacity rather than fixed-capacity floors, and it needs
matched corpora or the corpus confound returns through the back door. Both conditions
are already satisfied by the control above: every rung was re-headed at hidden
256/1024/4096 on the same 0.45M-token corpus. At the largest reader the mid-depth floor
is \textbf{15.3--16.3 bits at every scale with no monotone trend} (Spearman $+0.09$
against $\log$ parameters), and sensitivity to reader capacity \emph{falls} with model
size (0.63 bits per capacity doubling at GPT-2 to 0.40 at 6.9B; Spearman $-0.77$).
Larger models need \emph{less} reader capacity to reach their floor --- the opposite of
the failure mode the objection describes --- so the scale claim stands as written. We
do not fit a saturating extrapolation: three capacity points are too few, and two of
six rungs return non-physical asymptotes when one is attempted. The largest-reader
floor is the proxy and the slope is the trend.

\section{Why it works}\label{sec:why}
A 213k-parameter head, reading a frozen residual stream through no gradients of its
own, predicts roughly 75--80\% of the bits of a random causal function of the prefix.
That was the original surprise of this instrument, and earlier drafts explained it by
calling the whole thing ``the syndrome.'' \textbf{Two distinct mechanisms are doing
two distinct jobs, and conflating them hides both the reason it works and the two
different ways it can fail.}

\paragraph{Reading is despreading.} We use \emph{channel}, \emph{sender} and \emph{reader} in the
senses defined in \citep{paper1} and do not redefine them here. The companion census measures, on
the same object this seal reads, that a single feature's signal-to-interference ratio
along its own direction is $-28$ to $-30$\,dB --- far below anything a coordinate-wise
reader could pick up --- while correlating against the \emph{full} direction recovers
the feature's presence at AUROC 0.993--0.995, against 0.89--0.92 for the best single
coordinate. The residual stream is a spread code: information about the prefix is
smeared across many coordinates at low per-coordinate amplitude, so a reader that
correlates across a whole direction collects a processing gain that no single
coordinate offers. Our head does exactly this, 64 times in parallel, once per bit.

Two consequences follow, and the second corrects the framing this paper used to carry.
First, the floor should move with \emph{reader capacity} rather than with the
difficulty of any particular bit --- which is what Section~\ref{sec:armh} measures
(capacity moves the floor by ${\approx}2.5$ bits from hidden 256 to 4096; per-bit
error is uniform, with no unlearnable bit). Second: \textbf{``the stream carries a
hash'' was always the wrong framing.} The key is not cryptographic. It is the sign
pattern of a frozen random \emph{smooth} function of the prefix, and random smooth
functions of linearly-encoded prefix statistics are shallow-decodable in a way a real
hash would not be. The right statement is that \emph{the stream carries prefix
information redundantly enough that random projections of it survive} --- which is a
claim about the stream, and is the one the census supports.

\paragraph{Catching is authentication.} A swapped residual state is not an anomalous
state. It is a perfectly valid state --- for a \emph{different} prefix. Nothing about
it is out of distribution, and this is measurable rather than rhetorical: Mahalanobis
distance sits at 0.500 on swap at every rung of the scale ladder, exactly chance, while
the head detects it at 0.96--0.98. The head is not noticing that the state is strange.
It is noticing that the bits despread out of the state disagree with the key computed
from \emph{this} input. That is authentication, in the ordinary sense: a message
authentication code fails not because the message is malformed but because it does not
match the context it is presented in. It is also the cleanest available statement of
what the instrument certifies --- \emph{this activation belongs to this prefix} --- and
of what it does not.

\paragraph{They fail in different ways, which is the practical reason to keep them
apart.} Despreading degrades with reader capacity: a smaller head collects less
processing gain, the floor rises, and detection of small perturbations goes first.
Authentication degrades when an adversary can compute the key: the state is still
being read perfectly, and the check is still being computed correctly, but the
comparison has stopped being informative. Section~\ref{sec:limits}'s adaptive-attack
results are an authentication failure, not a despreading failure, and no amount of
extra head capacity would address them.

\section{Limitations}\label{sec:limits}
\paragraph{Census results and intervention results, kept apart.} Sections~\ref{sec:armf}
through \ref{sec:armh} and the monitor are \emph{measurements on frozen models}: forward
passes, cached activations, and a small head trained outside the model. They cost one
activation dump per model and they are expected to replicate at any scale --- which is
why the scale ladder could be run at all. Section~\ref{sec:lessons}'s design lessons come
from \emph{small systems trained from scratch}, and they are not evidence about language
models; they are where the construction came from. The distinction is not a hedge in a
limitations list: it determines which rows of this paper a reader may quote about a
frontier model.

\paragraph{Per-model datasheets do not transfer.} Every calibrated constant here --- the
clean floor, the detection thresholds, the windowed monitor's level, the Mahalanobis
companion's operating point --- was measured on a specific model with a specific
head-training corpus. Cross-domain covariance distance on this class of stream is
0.73--0.87 against a null of 0.05 \citep{paper1}, so channel statistics do not carry
across corpora, let alone across models. Every deployment needs its own calibration pass;
none of the numbers in this paper are defaults.


It does not detect prompt injection or any attack that lives in the input
text --- those produce valid states --- nor small adversarial perturbations of the
activations, nor an adversary who holds the key. It is a seal on the channel between
the model's own computations, not a judgment about what the model computed. Beyond
that paragraph: every corruption here is synthetic, applied to cached activations or
cache tensors; the monitor has not been run on a served model under KV-cache eviction,
quantisation or speculative decoding, so the base rate at which its calibrated level
holds in production is unmeasured. The certificate is statistical (a floor of 15--17
wrong bits, not zero), and the key must stay secret: with the key public an adaptive
attacker in activation space drives the syndrome below the floor at every budget, and
the two-sided statistic recovers only part of it (0.72--0.84 at $W{=}32$). Whether a
model fine-tuned against the head can carry information through a checked code is the
subject of a companion paper that publishes after this one: on a small recurrent testbed it can,
through spare code capacity the seal does not see.

\paragraph{Reproducibility.} All numbers are regenerated by \texttt{uv sync \&\& uv run
pytest} and then, in order: \texttt{uv run python -m ecc\_repr.eval lam0 systematic}
and \texttt{uv run python -m ecc\_repr.eval lam0 lam10 3b} (Table~\ref{tab:r3});
\texttt{uv run python -m ecc\_repr.arm\_b} and \texttt{uv run python -m ecc\_repr.arm\_a}
(Table~\ref{tab:mac}, sidebar); \texttt{uv run python -m ecc\_repr.arm\_f cache \&\& uv run
python -m ecc\_repr.arm\_f} and \texttt{uv run python -m ecc\_repr.arm\_f\_extras}
(Table~\ref{tab:armf}, Fig.~\ref{fig:loc}); \texttt{uv run python -m ecc\_repr.arm\_e}
(Table~\ref{tab:ef}); \texttt{uv run python -m ecc\_repr.kv\_mac} (Table~\ref{tab:armg});
\texttt{uv run python -m ecc\_repr.windowed} (Table~\ref{tab:window}); \texttt{uv run
python -m ecc\_repr.fuse resid kv} and \texttt{uv run python -m ecc\_repr.gencal}
(Tables~\ref{tab:fuse}, \ref{tab:gencal}); \texttt{uv run python -m ecc\_repr.scale rung
--rung <r>} for each rung, \texttt{uv run python -m ecc\_repr.scale rung --rung <r>
--corpus small} for the corpus control, then \texttt{uv run python -m ecc\_repr.scale
time \&\& uv run python -m ecc\_repr.scale agg \&\& uv run python -m ecc\_repr.scale
corpus} (Table~\ref{tab:scale}); figures by \texttt{uv run python -m

its 3-seed replication is in the repository); error bars are one standard deviation
